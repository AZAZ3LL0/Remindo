## CONTRACT GAP

Не хватает контракта, типа, поля БД, статуса enum, CallbackData-фабрики или текста — **СТОП**. Код с выдуманным контрактом не пиши. Выдай блок и жди обновления ядра:

```
CONTRACT GAP
Что нужно: <точное имя поля/типа/джоба и где оно требуется>
Зачем: <задача, которая без него не закрывается>
Предлагаемая форма: <сигнатура, тип колонки, JSON-пример>
Затрагивает: <файлы из списка общих>
Временная заглушка: <что делаешь локально, пока ядро не обновлено>
```

Дальше открой issue с меткой `contract-change` и продолжай на локальной заглушке. Аппендит контракт в `tech.md` и бампает версию только тимлид.

Тимлид и разработчик — один человек, но роли не сливаются: правка ядра идёт отдельным PR с меткой `contract-change` и бампом версии, а не заодно внутри PR со слайсом. Сессия, ведущая слайс, `tech.md` не редактирует.

Правило действует и на мелочи: не хватает статуса в enum — это `CONTRACT GAP`, а не `str` вместо enum. Не хватает строки пользователю — это ключ в `texts.py` через тимлида, а не литерал в хендлере.

## Эталон

Твой слайс повторяет раскладку эталонного слайса «Вода»: `app/domain` → `app/db/repositories` → `app/services` → `app/bot/handlers` → тесты всех четырёх обязательных типов. Сверяйся с ним, не изобретай свою структуру.

## Жёсткие правила кода

- Ноль `datetime.now()`, `datetime.utcnow()`, `date.today()`. Только `Clock`. Все datetime timezone-aware, в БД UTC.
- `app/domain/` не импортирует `db`, `bot`, `gateways`, `services`. Ноль IO.
- Транзакции открывает только `services/`. Репозиторий не коммитит.
- Хендлеры тонкие: разобрать апдейт, вызвать сервис, отрендерить. Логики в хендлере нет.
- Строки пользователю — только через `T(...)` из `texts.py`.
- Внешнее — только за протоколом. В тестах и в dev работает `FakeBotGateway`.
- `os.environ` вне `app/core/config.py` запрещён.

## Тесты

Тесты выводятся из критериев приёмки задачи, не из реализации. Тест, зеркалящий код, не считается тестом.

На каждый слайс обязательны:
1. контрактный тест на стыке (payload расписания, валидация в `FakeBotGateway`, round-trip CallbackData ≤ 64 байта);
2. тест идемпотентности на каждый цикл воркера и каждую реакцию — прогон дважды даёт ровно один эффект;
3. тест пути ошибки через фейк (`TelegramRetryAfter`, `TelegramForbiddenError`, таймаут);
4. property-based Hypothesis на чистой логике (`recurrence`, `quiet_hours`, `retry`, `stats`). Инварианты перечислены в `tech.md` §10.

Нужен `sleep` — тест написан неправильно, двигай `FakeClock`.

## Рабочий цикл

Одна задача за раз из дорожной карты `tech.md` §15. Сфокусированный дифф, не всё приложение сразу.

Ветка из задачи → маленькие коммиты по ходу → PR → CI → ревью → мёрдж → автодеплой из `main`.

Коммиты, PR и комментарии в коде — только на английском. Формат всегда `type(scope): summary`, `type` из `feat|fix|test|refactor|chore|docs`, императив, строчная, без точки, до ~50 символов. Тело только про *почему*.
